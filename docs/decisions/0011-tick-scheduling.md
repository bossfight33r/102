# 0011. Планирование в tick

**Решение.** Нет отдельной очереди: у каждой задачи функция `due(app, now)` по состоянию БД (время опроса каналов, время последнего снимка, журнал квоты, наличие неразобранных аутлайеров, отправлен ли дайджест на локальную дату). Поэтому повторный tick ничего не делает и не тратит квоту. `task_runs` хранит время и статус последнего запуска (ok/deferred/error) для диагностики. Отложенная задача (QuotaDeferred) повторится на следующем tick. Параллельные запуски блокирует `fcntl.flock` на `data/tick.lock`.
