# 0014. Batch API для анализа

**Контекст.** Анализ не срочный: дайджест утром, а Batch API стоит вдвое дешевле.
**Решение.** `analysis.use_batch: true` — tick подаёт до `batch_max_items` неразобранных аутлайеров одним пакетом (custom_id = video_id), запоминает пакет в `llm_batches` (миграция v3) вместе с хешем входа и на следующих tick забирает результаты. Валидный ответ → Analysis (стоимость × `llm.batch_discount`), невалидный/ошибка → бэкофф 24 ч, пакет старше `batch_timeout_hours` закрывается. Дайджест ждёт незавершённые пакеты до `digest.wait_analysis_hours`. Серверный fallback при отказе в пакетах не поддерживается. Без повторной попытки с текстом ошибки (в синхронном режиме она есть).
Бюджет: потрачено за 24 ч + пакеты в полёте × средняя стоимость анализа (30 дней, иначе `batch_cost_estimate_usd`) + новые элементы ≤ `max_cost_usd_per_day`. Истёкший пакет отменяется у Anthropic.
**По умолчанию выключено** до проверки на реальном API; включение — одна строка в settings.yaml.
